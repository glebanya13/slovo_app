# Google Play: раздел «Безопасность данных» (Data safety)

Заполняется в Play Console → **Содержание приложения → Безопасность данных**.
Ответы основаны на фактическом поведении кода (см. `docs/APPSTORE_PRIVACY.md`,
`lib/core/account.dart`, `lib/core/auth_service.dart`, `firestore.rules`).
Текст политики: `https://davinchi.dev/apps/slovo/privacy.html` — должен совпадать с этими ответами.

## Общие вопросы

| Вопрос | Ответ |
|---|---|
| Собирает ли приложение какие-либо данные пользователей? | **Да** |
| Передаются ли данные третьим лицам («предоставление»)? | **Нет** — все получатели (Google Firebase, Gemini API, ElevenLabs, Cloudflare) обрабатывают данные как доверенные исполнители приложения, а не как самостоятельные получатели. Это соответствует определению «передачи» в справке Play. |
| Шифруются ли данные при передаче? | **Да** (везде HTTPS/TLS: Firebase, proxy, Gemini, ElevenLabs) |
| Есть ли способ запросить удаление данных? | **Да** — удаление аккаунта в приложении (`Настройки → Аккаунт → Удалить аккаунт`): стирает `users/{uid}`, все подколлекции и push-токен (см. `account.dart:71`). |

## Какие типы данных заявить

Формат: тип → collected? / optional? / purpose.
Для каждого типа в форме также спрашивают про **временную обработку** (ephemeral):

| Тип | Временно? | Обязателен? | Цели |
|---|---|---|---|
| Email | Нет | Нет (опционально) | Управление аккаунтом |
| Имя | Нет | Нет (опционально) | Функции приложения |
| Аудио | Да (не храним нигде) | Нет (опционально) | Функции приложения |
| Пользовательские данные | Нет | Нет (опционально) | Функции приложения + Персонализация (традиция адаптирует контент) |
| Журналы сбоев | Нет | Да (Crashlytics нельзя отключить) | Аналитика |
| Идентификаторы | Нет | Да (нет opt-out) | Функции приложения |

«Реклама или маркетинг» и «Предотвращение мошенничества» не отмечаются нигде.

### 1. Личная информация → Электронная почта
- **Собирается**: да (Firebase Auth, вход по email; дублируется в `users/{uid}.email`).
- **Необязательно**: да — приложение работает анонимно, email нужен только при входе по email.
- **Назначение**: функциональность приложения (аутентификация, восстановление пароля).

### 2. Личная информация → Имя
- **Собирается**: да (Google/Apple-вход передаёт displayName; хранится в `users/{uid}.name`).
- **Необязательно**: да.
- **Назначение**: функциональность приложения (профиль).

### 3. Аудио → Записи голоса / аудио
- **Собирается**: да — голосовой ввод (распознавание речи, `speech_to_text` + `RECORD_AUDIO`).
  Приложение само аудио не хранит и на свои серверы не отправляет: распознавание выполняет системная служба (на Android — служба распознавания Google).
- **Необязательно**: да — можно набирать текст вручную.
- **Назначение**: функциональность приложения.

### 4. Данные и действия в приложении → Другие пользовательские данные
- **Собирается**: да — молитвы, дневник, практика, закладки и прогресс чтения, сообщения в чате с ИИ.
  Синхронизируются в Firestore (`users/{uid}/data/*`, список ключей в `firestore.rules`); текст вопросов и контекст молитвы уходят в Gemini API через Cloudflare-прокси; текст для озвучки — в ElevenLabs.
- **Необязательно**: да — без этого функции недоступны, но базовая работа возможна.
- **Назначение**: функциональность приложения.
- Примечание: отдельной категории «религиозные убеждения» в форме Play нет — контент молитв/дневника покрывается именно этим пунктом. Политика обязана раскрывать чувствительность данных (раскрывает).

### 5. Данные приложения и производительность → Журналы сбоев
- **Собирается**: да (Firebase Crashlytics).
- **Необязательно**: нет.
- **Назначение**: функциональность приложения (стабильность/диагностика).

### 6. Идентификаторы → Другие идентификаторы
- **Собирается**: да — Firebase UID и push-токен FCM (хранятся в `users/{uid}`).
- **Необязательно**: нет.
- **Назначение**: функциональность приложения (пуш-уведомления, синхронизация).

## Что НЕ заявлять

- **Реклама, трекинг** — нет (нет рекламных SDK, нет cross-app tracking).
- **Аналитика** — нет (`firebase_analytics` не подключён).
- **Биометрия** — обрабатывается на устройстве (`local_auth`), наружу не передаётся.
- **Фото/видео, файлы, контакты, календарь, финансы, здоровье** — не собираются.

## Связанные требования Play (не забыть)

1. **Политика конфиденциальности** — URL в разделе «Приложение» → обязателен, текст должен совпадать с этими ответами.
2. **Удаление аккаунта через веб** — если приложение позволяет создавать аккаунты, Play требует URL веб-ресурса для запроса удаления (отдельный вопрос «Удаление данных» в «Содержании приложения»). В приложении удаление есть (`account.dart:71`); добавить на страницу политики раздел/ссылку с инструкцией и контактным адресом.
3. **Целевая аудитория** — если заявлен возраст 13-/18+, ответы должны согласовываться (религиозный контент не детский).
4. Consistency: ответы выше совпадают с `ios/Runner/PrivacyInfo.xcprivacy` и App Store Connect (см. `APPSTORE_PRIVACY.md` §4).
